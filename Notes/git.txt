DAILY WORKFLOW
==============

1. Verify changed files

git status


2. Stage changes

git add .


3. Create commit

git commit -m "Description of change"

Examples:

git commit -m "Add config test command"

git commit -m "Add validate all command"

git commit -m "Implement LastSeenUtc"


4. Upload commit(s) to GitHub

git push


WHAT DOES GIT ADD . MEAN?
=========================

The dot means:

Current folder

Example:

git add .

means:

Add everything in the current folder and all subfolders
to Git's staging area.

Current folder:

C:\_Ed\SW\BC\BCETL

Files excluded by .gitignore are skipped.

===========================

Example:

The text:

Purpose:

WHAT DO THE ++++ SYMBOLS MEAN?
=============================

Example:

SalesHeaderValidationService.cs | 141 ++++++

The number:

141

approximately represents lines added.

The plus signs are a visual histogram.

More plus signs:

++++++

means:

Larger contribution to the commit.

Fewer plus signs:

+

means:

Smaller contribution to the commit.

The plus signs are not actual line counts.

SECRETS RULE
============

Never commit:

BCETL_CLIENT_SECRET
SQL passwords
OAuth tokens
Connection-string passwords
API keys

GitHub Push Protection will block them.

Instead document:

Client Secret:
Stored in BCETL_CLIENT_SECRET environment variable.

Do not store secrets in Git.


RECOVERY COMMANDS
=================

Undo most recent commit
But keep file changes

git reset --soft HEAD~1

Result:

Commit removed.
File changes remain.


Reset branch to earlier commit

git reset --hard bc86af2

Result:

Branch returns to commit bc86af2.
Later commits are discarded.

Use carefully.
